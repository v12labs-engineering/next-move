The baseline is the parent rollout's `source-inventory.json`, captured at 06:37:22 UTC. This agent has made no database changes, activated no sources, and touched no Vercel resources. ## Qualcomm: verified contract, held on repeated provider throttling

[Qualcomm's corporate careers page](https://www.qualcomm.com/company/careers) links to [its public career search](https://careers.qualcomm.com/careers). The official India UI reported **541 positions**, across all professions and posting dates. The ordinary isolated browser exposed these requests when selecting India, Latest, and Next:

```text
GET https://careers.qualcomm.com/api/pcsx/search?domain=qualcomm.com&query=&location=India&start=0&sort_by=timestamp&
GET https://careers.qualcomm.com/api/pcsx/search?domain=qualcomm.com&query=&location=India&start=10&sort_by=timestamp&
GET https://careers.qualcomm.com/api/pcsx/position_details?position_id=446721896079&domain=qualcomm.com&hl=en
```

The public search and detail both returned HTTP 200 from local Docker. Search provides numeric position identity, requisition ID, title, explicit India locations, normalized `IN` locations, `postedTs`, and the canonical `/careers/job/<id>` path. Detail supplies the complete HTML `jobDescription` and repeats identity, date, and location. The checked [AI platform role](https://careers.qualcomm.com/careers/job/446721896079) has requisition 3098865 and a publication date matching the displayed age. `creationTs` is separate and is not used as the publication date. Generic work-location metadata is not reliable enough to infer remote status; absent corroboration stays unknown.

[The provider's robots file](https://careers.qualcomm.com/robots.txt) explicitly allows `/careers` and `/api/pcsx` despite a default disallow rule. The reader restricts requests to this exact HTTPS host and the observed public paths. It accepts only `eightfold:qualcomm-india`, company Qualcomm, board `qualcomm-india`, and empty configuration. It does not enable arbitrary tenants or use authentication.

The first sequential inventory attempt stopped after four pages: offset zero reported 541, whereas offset 40 reported 542 and overlapped a prior boundary. A later response contained the provider's temporary refusal text. Research stopped and imposed a hold until at least 07:09 UTC. **The 541 count is not a verified fresh or eligible inventory, and the source is not activation-ready.** The failed page check is retained as evidence; the reader rejects moved, duplicate, incomplete, fuzzy, or unsorted inventories rather than publishing a partial snapshot.

After that hold, a complete reader attempt started at 07:09:20 UTC and verified two pages: 20 fresh India observations, nine eligible roles. At 07:10:09 UTC, the next public search returned **HTTP 429**, with no `Retry-After` header. Research stopped immediately and imposed the standard conservative 15-minute hold through 07:25:09 UTC. The source remains inactive and no activation manifest exists. The incomplete response sequence and refusal are saved under `direct/qualcomm/`; partial counts do not count toward additions.

Implementation is in `lib/server/catalog/connectors/eightfold.ts`; migration 086 registers the fixed scope without creating a source. Six focused tests cover full details and exact publication dates, category projection, raw observations, early-career policy, foreign/ambiguous locations, mismatched identity, partial/repeated pages, robots, HTTP backoff, and the 086→087 migration sequence. Complete live reader preflight remains a separate rollout gate.

## Barclays: complete and activation-ready

[Barclays' official India search](https://search.jobs.barclays/location/india-jobs/13015/1269750/2/1) returned HTTP 200 with **338 results, 22 pages, and 16 results per page**. The page supplies explicit current-page and total-result metadata and a public Next link to page 2. Only `#search-results-list` is inventory; other page sections include unrelated recommendations. [Its robots resource](https://search.jobs.barclays/robots.txt) returned an unrestricted generic user-agent group.

The [DevOps Engineer detail](https://search.jobs.barclays/job/pune/devops-engineer/13015/98454849344) returned HTTP 200 from Docker and contains `JobPosting` JSON-LD: full description, `datePosted: 2026-11-17`, employer Barclays, country India, city Pune, canonical URL, and requisition `JR-0000110105`. Listing cards only show day/month and may differ from the detail's date; those cards cannot establish an exact posting year or fresh eligibility.

The fixed `talentbrew:barclays-india` reader is implemented in `lib/server/catalog/connectors/talentbrew.ts`; migration 088 registers its identity and source-pool membership without activating anything. The reader traverses the entire public inventory, requires exact page counts and observed Next links, compares adjacent boundaries, validates employer and canonical identity, and applies the 30-day window to the detail's exact date. It preserves current profile-category behavior and does not infer work mode. Both readers reject HTML masquerading as robots, follow no arbitrary redirects, and retain the shared bounded HTTP/backoff behavior.

The complete reader finished at **07:20:04 UTC**, using the fixed snapshot start **07:02:36 UTC**. It checked all **338 postings across 22 pages** and verified **210 unique fresh India observations**, of which **113 unique jobs** meet current category and early-career eligibility: 91 software, 10 data, nine product, and one each in design, marketing, and sales. These are eligible source-preview counts; actual net-new additions still require parent-owned publication and comparison with the platform baseline.

All **403 public responses** succeeded. The full inventory has **338 distinct canonical URLs and 338 distinct provider requisition IDs**, so no requisition aliases inflate the count. Full fresh descriptions total 1,372,853 bytes; eligible descriptions total 748,464 bytes; the largest response is 579,502 bytes. No size-budget increase is needed. The baseline directory contained no Barclays or Qualcomm source. An unactivated Barclays Workday candidate was already marked `needs_review`; it is not activated alongside the verified direct feed.

The initial run stopped on page 21 because an older official posting uses an eight-digit legacy requisition, `90390427`, instead of the newer `JR-...` form. The narrow fix accepts either observed format while retaining exact canonical numeric-path, employer, country, body, and date checks. A regression proves that an old posting remains excluded. Four such legacy requisitions were present, all dated 25 July 2024. The final reader replayed the 397 already-saved HTTP 200 responses and fetched the remaining six responses; no completed page had to be fetched again. This preserves the original snapshot time and the failed receipt as evidence.

Twelve combined Qualcomm and Barclays tests pass, including migration order 086→087→088 with all three connector kinds preserved. ESLint, TypeScript, and diff checks pass; a separate read-only code/SQL review found no rollout-blocking defect. A complete offline replay passed at **07:21:23 UTC** against the final source code and reproduced every job and count. Evidence is under `direct/barclays/`: `requests.json`, every numbered `response-*.txt`, `preflight-failure.json`, `preflight.json`, `observations-full.json`, `identity-audit.json`, `replay.json`, and `activation-ready.json`. The activation manifest contains exact source identity, complete status, snapshot/completion timestamps, pages, fetched/accepted/unique counts, category counts, byte measurements, replay verification, and the runtime hash. This agent has not activated or published it.
